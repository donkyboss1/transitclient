# HTTP-01: требования клиентского установщика

## 7. Публичный установщик на основе selfsteal

Уточнение владельца 10.10.2026: собственный Caddy всегда устанавливается
через Docker Compose, как у DigneZzZ; native Caddy/systemd не вводится.
Автономная команда управления — `transitclient`, существующий `transit`
не перезаписывается. До установки выполняется диагностика ОС/systemd/Docker,
веб-серверов и слушателей; VPN 443, HTTP 8080 и HTTPS 127.0.0.1:9443 вводятся
отдельно. Существующий веб-сервер допускает изолированный экземпляр либо
ручную интеграцию по инструкции с backup/validate/reload/rollback.
Переработка пакета: [installer-spec.md](installer-spec.md).

Исходник: `H:\Dev\Server OPTIMUS\DigneZzZ\remnawave-scripts\selfsteal.sh`,
локальная версия 2.10.0. Не изменять исходный репозиторий в рамках этой задачи.
Единственная рабочая папка: `H:\Dev\transitclient`; публичный репозиторий
`https://github.com/donkyboss1/transitclient`, ветка `main`.


Для первой версии оставить **Caddy + готовые сертификаты acme.sh**. Сохранить
полезные проверки, установку зависимостей, Docker Compose, локальный HTTPS-сайт,
простую заглушку, резервирование конфигурации и команды обслуживания.
Ветка Nginx, Unix-сокеты, TLS-ALPN-перенаправления 443 и QUIC
не обязательны: не переносить лишние ветки, если они усложняют новый
сценарий. Исходные авторские уведомления сохранить; проверить условия исходника
и зависимостей перед подготовкой пакета для публикации.

Обязательная адаптация:

Уточнение 10.10.2026: каталог из 11 сайтов перенесён в 1.2.0; выбор и загрузка
через `transitclient template`, с проверкой хешей, резервированием и откатом.

1. Интерактивная инструкция на русском: попросить вручную ввести выданный
   домен, проверочный порт из бота и при необходимости ожидаемый IP релея.
   Проверить синтаксис, показать параметры перед установкой и сохранить их
   локально. API-адрес, ключ установки и регистрация ноды не нужны.
2. Проверка поддерживаемой ОС, архитектуры, root/sudo, зависимостей, занятого
   проверочного порта, локального selfsteal-порта и существующей установки.
   Базовая матрица — Ubuntu 22.04/24.04/26.04; неподтверждённую совместимость
   не выдавать за проверенную. Установки и удаления пакетов не выполнять на
   машине разработчика при локальных тестах.
3. Проверка DNS не требует совпадения с IP backend. Если клиент ввёл ожидаемый
   IP релея, сравнить его с DNS; иначе показать полученные A/AAAA и объяснить,
   что они должны вести на релей. Не обходить все проверки одним `--force`.
4. Проверочный порт по умолчанию 8080, допустимы порты от 1024 до 65535.
   Скрипт использует значение, которое уже указано в заказе. Если оно занято,
   предложить свободный вариант и объяснить необходимость изменить порт
   в боте, дождаться применения маршрута и повторить установку с тем же
   значением. Не менять порт молча и не останавливать чужой процесс.
   Сохранить согласованный порт для последующих продлений.
5. Установить фиксированную проверенную версию acme.sh, явно выбрать Let's
   Encrypt, использовать HTTP-01 standalone и `--httpport <порт>`.
   Не использовать `--alpn`, iptables redirect клиентского 443 и принудительный
   выпуск `--force` при каждом повторе установки.
6. Выпуск/продление организовать через один общий рабочий механизм: временное
   разрешение firewall, проверочный сервис, ACME, установка сертификата,
   применение Caddy, очистка. Порт разрешается всем источникам только на время
   проверки. При уже существующем разрешении его не удалять после операции.
7. Автоматически управлять только поддерживаемым локальным firewall. Не включать
   UFW на клиенте без подготовки SSH и понимания текущих правил; не очищать
   firewall целиком. Провайдерский firewall/NAT может требовать ручного открытия
   выбранного порта; дать конкретную инструкцию и диагностировать недоступность.
8. Проверить SAN домена, срок и доверенную цепочку, соответствие сертификата
   ключу. Ошибка выпуска не заменяется автоматически self-signed/`tls internal`.
9. Применять сертификат в **реальные рабочие пути Caddy**, с корректными правами
   и доступом контейнера. Учесть, что исходный installer копирует переданные
   сертификаты в свою папку: обновление только исходной копии недостаточно.
10. Caddy использует явные пути cert/key; не пытается параллельно выпускать свой
    сертификат. Selfsteal HTTPS слушает локально, например `127.0.0.1:9443`.
    Не публиковать этот порт и не запускать постоянный публичный HTTP-сайт 80
    на backend ради этой схемы. Удалить конфликтующие правила из шаблонов.
11. После применения проверить, какой сертификат действительно выдаёт локальный
    Caddy с нужным SNI. Показать результат в терминале; ни результат, ни ключ
    не отправлять в «Транзит». Подсказать следующий шаг в боте.
12. Дать инструкцию Remnawave/Xray: endpoint после запуска — выданный домен и
    персональный VPN-порт; для REALITY serverNames — выданный домен, target —
    локальный selfsteal, Caddy xver=0. VPN inbound и HTTP-порт проверки различны.
    Не выводить приватный ключ REALITY. Проверить рекомендации по используемой
    версии Xray; ordinary TLS и REALITY не смешивать в одной инструкции.

Подготовить CLI установки и обслуживания: `install`, `status`, `diagnose`,
`renew`, `update`, `uninstall` (названия можно уточнить). Повтор установки
сохраняет сертификат, ACME account и настройки; не создаёт новую аренду.
Удаление касается только ресурсов этого пакета и предупреждает о прекращении
продления; другие контейнеры, firewall-правила и VPN-ноду не удалять.

Обновление идёт только из нового проекта по фиксированной версии с проверкой
артефакта. Оригинальные SCRIPT_URL/UPDATE_URL заменить, чтобы upstream update
не затёр адаптацию. Зафиксировать версии и хеши зависимостей, запретить сетевое
автообновление acme.sh в обход выбранного механизма. Настройки публичного URL
пакета и версии должны быть конфигурацией, без вымышленного рабочего адреса.

## 8. Автоматическое продление

Установщик оставляет локальное задание **systemd timer** и постоянную конфигурацию
0600. Клиент вручную запускать скрипт для продления не должен. Исключить второй
независимый cron acme.sh для той же установки; чужие cron-задачи не удалять.
Проверка необходимости продления выполняется регулярно с разнесением времени
запуска и учётом правил выбранной версии acme.sh/CA; не привязывать алгоритм к
неизменяемому сроку сертификата «90 дней».

- Между установкой, обновлением и продлением — общий flock, без конкурирующих
  попыток и двойных временных firewall-правил.
- Если продление не требуется, сертификат не перевыпускается; временный сервис
  и открытие порта включаются для фактической ACME-проверки.
- На время операции открывается сохранённый порт; таймаут ограничен. Очистка
  предусмотрена при успехе, ошибке, SIGTERM, превышении таймаута и reboot.
  Одного shell trap недостаточно для SIGKILL: нужен управляемый временный
  ресурс/сохраняемый маркер и гарантированная последующая сверка.
- При ошибке сохранить прежний действующий сертификат и Caddy, повторять с
  задержкой, не скрывать ошибку таймера. Состояние видно в `status`/`diagnose`.
- Успешное продление проверяет новые файлы, безопасно применяет их и проверяет
  сертификат действующего Caddy. Обновлённый файл без применения — не успех.
- Установщик и таймер не обращаются к API «Транзита»: маршрут на релее уже есть.
  Остановка аренды удаляет маршрут; клиентский таймер позднее выдаёт понятную
  ошибку недоступной проверки. Существующий сертификат автоматически не отзывается.
