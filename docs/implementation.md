# Transit Client: локальная реализация и приёмка

## Повторная установка и подтверждения, 11.10.2026

В 1.4.1 повторная установка после `uninstall` использует входящий проверенный
пакет. Прежний runtime в `/opt/tenant-selfsteal` не подменяет его версию.
Данные прежней установки остаются в отдельном root-only backup с датой и временем.
При существующей конфигурации переход на другую версию требует `update`.
Все подтверждения используют `[y/N]`; только `y`/`Y` разрешают действие,
пустой ответ, `no`/`n` и прежнее русское `да` его отменяют.

Условия приёмки фиксируются до реализации:

- После удаления 1.3.3 установка входящего пакета 1.4.1 сохраняет в `/opt`
  именно 1.4.1; глобальный launcher обращается к этому пакету.
- Отмена плана и выбор инструкции не заменяют сохранённый runtime.
- Чужие каталоги и символические ссылки не перезаписываются.
- Действующая установка другой версии возвращает `UPDATE_REQUIRED`.
- Сбой замены пакета оставляет прежний пакет восстановимым.
- Удаление сохраняет данные в отдельной папке и не перезаписывает прежние backup.
- ACME использует только собственное хранилище; сторонние аккаунты не импортируются.

Регрессионные проверки выполняются без реальных Docker/UFW/ACME операций.
Полный прогон: **314 passed, 7 skipped** на Windows (symlink/POSIX permissions).
Ruff и offline PTY-приёмка в WSL Ubuntu прошли. Реальная установка и выпуск
сертификата не выполнялись.

## Отдельный проект и сайты, 10.10.2026

В 1.3.2 первая установка выбирает случайный сайт без каталога/вопроса,
подтверждение плана использует `[y/N]`. Меню смены сайта и --template сохранены.
Ошибка Compose показывает этап, код и классифицированную причину без сырого
stdout/stderr; общий код 255 сам по себе не доказывает причину сбоя Caddy.

В 1.3.3 исправлен запуск официального образа: /usr/bin/caddy имеет
cap_net_bind_service=ep, поэтому при cap_drop ALL возвращается exec EPERM.
Добавлен только NET_BIND_SERVICE; read_only/no-new-privileges сохраняются.
Владелец подтвердил getcap и успешный caddy version с этим разрешением на
Ubuntu 26.04 / Docker 29.8.2. Это ещё не подтверждение работы HTTPS/продления.
Проверка caddy validate с прежним сертификатом также завершилась успешно.
Проверка исполняемого файла в контейнере без сети выполняется перед ACME.

Единственная рабочая папка — `H:\Dev\transitclient`. Исходники, тесты, инструкции
и релизы больше не хранятся в основном «Транзите». Правила — в `../AGENTS.md`.
`build_publication.py` собирает архив и обновляет `install.sh` прямо здесь.

Версия 1.2.0 добавляет каталог из 11 сайтов как у исходного selfsteal: выбор
при установке, случайный выбор, `transitclient template`, встроенную страницу
и откат. Источник и SHA256 каждого файла фиксируются в `templates.json`.
Подтверждена доступность закреплённого upstream и хеш его index.html.
Смена сайта сохраняет прежние файлы, проверяет HTTPS-ответ и восстанавливается
по журналу после прерывания. Сертификат и порты не изменяются.

Серверная установка/приёмка, выпуск сертификатов, коммит и push не выполнялись.
Локальные проверки 1.2.0: **140 passed, 5 skipped** (symlink на Windows), Ruff
и синтаксис Bash без ошибок. Эти проверки относятся только к клиентскому проекту.

## Переработка автономного пакета, 10.10.2026

`H:\Dev\transitclient` обновлён до 1.1.0 по
[ТЗ установщика](installer-spec.md). По решению владельца Caddy
всегда запускается через свой Docker Compose. Добавлены меню и глобальный
launcher `transitclient`, отдельный ввод VPN/HTTP/HTTPS, диагностика до установки,
идентификация TCP/Docker publications и запрет удалённого Docker context.
Существующие веб-серверы/ноды не изменяются; фрагменты ручной интеграции,
резервирование и откат описаны в документации автономного пакета.

Основной HTTPS bind — точный host loopback без Docker publication; для VPN
bridge выбирается существующая user-defined сеть с отдельным alias Caddy,
без изменения сети/Compose VPN-ноды. Admin Caddy использует собственный Unix
socket. TLS применяется через `reload --force` с проверкой выдаваемого сертификата,
TLS 1.3/h2. Добавлены ограниченный HTTP self-test без ACME и явная проверка
target через имеющийся OpenSSL выбранного VPN-контейнера.

Bootstrap проверяет закреплённый архив/SHA256/версию до запуска. Для публикации
выбран `donkyboss1/transitclient`, ветка `main`; `build_publication.py` создаёт
отдельный клиентский checkout, `install.sh` и архив в `dist`. Отправку коммита
выполняет владелец; серверных установок не выполнялось. Status читает
состояние без lifecycle lock/recovery, показывает сертификат/срок, timer и
безопасные коды ошибок. Владение проверяется перед остановкой Compose,
постоянных/transient units и заменой launcher. Обновление и смена локального
target сохраняют резервные копии и проверяют откат; удаление сохраняет config,
cert/key/account и не удаляет системные зависимости.

Локальная проверка: `python -m pytest tests` включает
все экспортируемые тесты пакета: **122 passed, 4 skipped** (Windows не разрешает
нужные symlink проверки). Ruff и Bash syntax проверены отдельно. Реальная
Ubuntu/архитектурная, NAT, staging/renewal/SIGKILL/reboot приёмка остаётся
обязательной перед заявлением серверной готовности; выпуск CA не выполнялся.


## Автономный публичный пакет

Исходники: [README](../README.md).
Исходный selfsteal 2.10.0 и соседний репозиторий не изменены.

CLI: install, configure (согласованный проверочный порт), status, diagnose,
renew, update, uninstall. Runtime Python stdlib, pinned acme.sh 3.1.6,
Caddy 2.11.4-alpine с OCI digest и Compose v5.6.0 с SHA256 для amd64/arm64.
Все лицензии поставляются; MIT адаптации не заменяет GPLv3 отдельного acme.sh.

ACME account/config сохраняются. HTTP-01 standalone временно открывает только
свой tagged UFW-rule; существующее разрешение не удаляется. Для другого
firewall требуется явный manual mode и инструкция. Caddy читает рабочие cert/
key через каталог поколений, публичного backend HTTP 80 нет, HTTPS доступен
только на loopback. Проверяются SAN/срок/цепочка/key и фактически выдаваемый
сертификат с SNI/h2; ошибка откатывает поколение. Self-signed fallback отсутствует.

В 1.3.0 мастер сокращён до домена и трёх портов; подробности — в diagnose.
firewall_setup.py строит read-only план включения UFW, сохраняет SSH и
обнаруженные службы, резервирует конфигурацию и готовит независимый watchdog.
Включение разрешено только после подтверждения плана и повторных проверок.
Для неизученных firewall/Docker-схем автоматическая активация запрещена.

Systemd timer проверяет необходимость каждые 6 часов с RandomizedDelay 45 минут;
due/ARI определяет acme.sh, нет force issuance или независимого cron. Общий
flock, transient ACME cgroup, ограниченный срок, tagged marker, watchdog и
boot recovery покрывают очистку и восстановление. Update принимает только
явный URL/версию/SHA256, проверяет архив, сохраняет предыдущий пакет и имеет
устойчивый журнал переименований. build_release.py создаёт исходный архив
с файлами в корне и checksum; никаких публикаций не выполняет.
