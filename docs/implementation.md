# Transit Client: локальная реализация и приёмка

## Ожидание HTTP-пути при запуске probe: 1.5.4, 27.10.2026

После восстановления подготовки чтение центра подтвердило applied HTTP-маршрут;
клиентский журнал показал старт и остановку probe в одну секунду без traceback.
В коде найдена и воспроизведена гонка: systemd `--service-type=exec` не ждёт
bind Python HTTPServer, а прежний цикл прекращал попытки при любом HTTP-ответе.
Последовательность 503 → корректный 200 ошибочно завершалась на первом 503.

Теперь 502/503/504 повторяются до пяти раз с паузой в пределах прежних 120 секунд.
Сохраняется проверка каждого A/AAAA и точного nonce. Ошибки 404/redirect/неверное
тело не считаются успехом. При отказе показываются адрес релея и безопасный
последний статус/класс сетевой ошибки, без тела ответа. Listener и operation
scope очищаются и после отказа; наличие HTTP evidence требует успешной проверки.

Добавлены девять сценариев: временные 502/503/504 → успех, готовность на пятой
попытке, постоянный 503, неверное тело без утечки содержимого, timeout/refused и
исчерпание общего бюджета. До исправления восемь новых проверок падали, включая
503 → 200; после исправления все девять и профиль lifecycle проходят.
Применён ponytail full. Полный pytest: **629 passed** в WSL Ubuntu от обычного
пользователя; Windows **587 passed, 42 skipped** (POSIX permissions/ownership,
symlink/flock/Unix socket; соответствующие сценарии прошли в Linux). Все
**16 групп PTY** на 80×40/48×20, Ruff, Bash syntax и Git diff check прошли.
Релиз 1.5.4 собирается штатным build_publication.py с новым архивом/SHA256;
прежние опубликованные архивы не заменяются.
Живые установка/ACME/systemd startup с исправленной версией не выполнялись.
Адрес backend сверён с выводом интерфейса клиента; доступность порта и успешный
проход нового теста требуют отдельной серверной проверки. Внешний 503 после
очистки временного listener сам по себе не доказывает сбой сети.

## Legacy firewall и временные версии программы: 1.5.3, 27.10.2026

Лог владельца подтвердил остановку перед ACME при выключенном UFW. Проверка
кода выявила дефект 1.5.2: смена домена переносила отсутствующий effective
из 1.4.6 как null; `.get(..., fallback)` не применял fallback при явном null,
и manual мог попасть в ветку управления UFW. В runtime и firewall plan теперь
используется сохранённая политика при пустом effective, при смене домена
явно сохраняется preserve либо ufw. Неразрешённый auto останавливается до
backup/изменения config. Явный ufw с выключенным UFW сохраняет запрет, получает
код UFW_INACTIVE и подсказку настройки. Автоматического включения или смены
политики нет. Реальный сохранённый firewall клиента не прочитан, поэтому по
одному логу нельзя отличить legacy manual/null от настоящего ufw/inactive.

Сообщение о замене программы сокращено до перехода версий Transit Client и
временного сохранения для восстановления. Режим установки показывает Caddy
с отметкой «Рекомендуем», собственный веб-сервер — с отметкой «Инструкция».

После подтверждённого HTTPS и завершения транзакций автоматически очищаются
проверенные `tenant-selfsteal.previous-<id>` и парные служебные update snapshots.
При отложенном первом выпуске очистка ждёт успешного renew и закрытия его
operation scope. До успеха/commit копии нужны для отката и не удаляются.
Проверяются родительский путь, ID, marker, версия, хеш controller, владелец,
состав пакета/snapshot и отсутствие ссылок. Неизвестные файлы/копии сохраняются
с предупреждением. Активная программа, recovery и полные backup сертификатов/
настроек не включены в эту автоочистку. Их отдельные подтверждения сохраняются.

Применён ponytail full. Полный pytest: **620 passed** в WSL Ubuntu от обычного
пользователя; Windows **578 passed, 42 skipped** (POSIX permissions/ownership,
symlink/flock/Unix socket; соответствующие сценарии прошли в Linux). Все
**16 групп PTY** на 80×40/48×20, включая полный текст длинных пунктов, прошли.
Ruff, Bash syntax и Git diff check прошли. Релиз 1.5.3 собирается штатным
build_publication.py с новым архивом/SHA256; архивы 1.5.2 и прежних версий
не заменяются. ТЗ и AGENTS.md сохраняются только локально и не публикуются.
Реальная установка, состояние сохранённой политики на клиенте, UFW/systemd,
выпуск ACME и VPN-подключение этой локальной проверкой не подтверждаются.

## Повторная установка и очистка сертификатов: 1.5.2, 27.10.2026

По поручению владельца добавлен выбор перед DNS-проверкой прежнего домена:
открыть меню установленной версии, настроить новый домен из бота или выйти.
Первая установка сохраняет прежний мастер. При запуске из обычного меню
можно продолжить текущую установку без открытия вложенного меню.

Новый домен проходит DNS, проверку портов, HTTP nonce и подтверждение
выдаваемого Caddy сертификата. Прежняя установка сохраняется в root-only
backup с manifest; живой admin socket не копируется и Caddy для backup не
останавливается. Сайт, общий ACME account и постоянные правила firewall
сохраняются. Используется входящий проверенный пакет с прежним механизмом
резервирования runtime. Журнал смены домена восстанавливает config, current
certificate, lifecycle, HTTP evidence и результат при ошибке или `_recover`.
Истёкший прежний сертификат не блокирует откат; ошибки публикации config/
lifecycle также входят в защищённый участок. Готовность откатанного старого
домена этим не подтверждается: его DNS/маршрут могли уже исчезнуть.

После успеха сертификаты прежних доменов группируются по DNS-имени; удаление
каждого домена требует [y/N]. Текущий сертификат, все поколения текущего домена,
общий ACME account и чужие хранилища защищены. Проверенные backup предлагаются
отдельно, с предупреждением об удалении всей копии и отдельным [y/N]. При
отказе явно сообщается о сохранённых ключах внутри backup. Пути и владение
повторно проверяются перед удалением; неизвестные ссылки, повреждённые копии
и многодоменные сертификаты сохраняются. Отмена очистки не откатывает новый домен.

Применён ponytail full. Проверки: полный pytest **588 passed** в WSL Ubuntu
от обычного пользователя; Windows **555 passed, 33 skipped** (POSIX ownership,
symlink/flock и Unix socket; соответствующие проверки выполнены в Linux).
Ruff, Git diff check, синтаксис обоих Bash-скриптов и все **16 групп controlling
PTY** на 80×40/48×20 прошли. Дополнены проверки bootstrap на обязательность
installation_flow.py с 1.5.2. Архив и bootstrap собираются штатным сборщиком
с новым VERSION и SHA256; прежние опубликованные архивы не заменяются.

Ограничения: реальные установка/переход со старой версии на Ubuntu, systemd
rollback/reboot/SIGKILL, DNS/relay/ACME и VPN-подключение не выполнялись.
Тесты моделируют хостовые операции, а TLS/Unix socket проверяются локально.
Следующий шаг — отдельная серверная приёмка владельцем: повторный bootstrap,
новый домен из бота, отказ/согласие очистки и проверка VPN после смены SNI/target.
В этой задаче владелец явно поручил агенту самостоятельные commit и push;
это разрешение не распространяется на серверные изменения.

## Исправления аудита Ponytail: 1.5.1, 16.10.2026

Исправлены семь пунктов аудита версии 1.5.0:

1. Откат units определяет собственный systemd InvocationID и не останавливает
   выполняющий его recover/renew process. Восстановленные units запускаются
   без ожидания после освобождения lifecycle lock; старый ACME worker не запускается.
2. Перенос данных restore и публикация config/lifecycle защищены журналом вне
   STATE и маркером владения. Прерванный перенос отменяется через `_recover`,
   повторный `restore` или `install`; данные сохраняются в отдельном
   `tenant-selfsteal-restore-interrupted-<id>`, исходный backup не меняется.
   Изменённые посторонним действием config/STATE блокируют автоматический откат.
   После фиксации config дальнейшая подготовка использует прежний lifecycle.
3. HTTP nonce проверяется отдельно на каждом опубликованном A/AAAA, с исходным
   Host, без proxy/redirect. Общий бюджет остаётся 120 секунд; успешный журнал
   содержит результаты по IP. Внешнее операторское подтверждение также требует
   проверки каждого адреса и сохраняет отдельный scope.
4. Повторная сборка той же версии допустима только с идентичным архивом.
   Другое содержимое требует увеличения VERSION; прежний архив не заменяется.
5. Bootstrap и update требуют renewal_schedule.py для версии 1.5.0 и новее.
6. Автономные тесты моделируют root-owned файлы и запускаются без настоящего
   root. Отрицательные проверки UID и владельца backup сохранены.
7. Удалены неиспользуемые evidence в firewall и регулярное выражение панели.

Локальная проверка исходников: **547 passed, 10 skipped** на Windows;
**557 passed** в WSL Ubuntu от обычного пользователя. Пропуски Windows:
symlink, POSIX permissions/ownership и реальный flock. Ruff и Git diff check
прошли; все **15 групп controlling PTY** успешны на 80×40/48×20, синтаксис
обоих Bash-скриптов проверен. Проверены прерывания до/после публикации STATE/config, повторное
прерывание отката, собственный systemd unit, неверные HTTP body/status/redirect,
IPv6 timeout, неизменяемость версии и отказ неполному пакету до системных вызовов.

Серверные установки, реальный systemd rollback, reboot/SIGKILL и ACME в рамках
этой задачи не выполнялись; локальные симуляции не заменяют серверную приёмку.

## Firewall и lifecycle 1.5.0, 13.10.2026

Новые установки используют auto; сложные native nftables/Fail2Ban/Docker
конфигурации сохраняются в preserve. Legacy ufw/manual сохраняют политику,
явная смена доступна в настройках Firewall. Автоматическое включение простого
UFW разрешает только обнаруженный SSH и выбранный VPN-порт; watchdog 180 секунд
отменяется только при доказанном новом SSH-транспорте, включая запрет подтверждения
через новый канал старого ControlMaster. Первый ACME отложен до HTTP nonce;
при NAT hairpin возможна явная операторская внешняя проверка с отдельным scope.

Timer запускается после commit и освобождения lock; running без NextElapse
корректен. Busy worker ждёт до 30 секунд и ставит один повтор через 5 минут;
ошибки ACME сохраняют повтор через час. Hook/lease/transient units имеют
install_id/operation_id; устаревшие обработчики не затрагивают новые операции.
Recovery использует атомарно выбранное полное поколение helpers. Update сохраняет
config, units и enabled/active state, а rollback не запускает прежний worker.
Удаление останавливает worker/retry, очищает Persistent stamp, сохраняет закрытый
backup с manifest. Финальное перемещение STATE восстанавливается по журналу вне
STATE. Restore выполняет проверенный входящий runtime, сохраняет исходную копию
и требует отдельного разрешения последующего ACME; смена домена снимает old current.

Локально: **522 passed, 8 skipped** на Windows, **530 passed** в WSL Ubuntu
с Linux OpenSSL/cryptography и реальным flock. Ruff, Git diff check и Bash syntax
успешны; все **15 групп controlling PTY** прошли на 80×40/48×20.
Отдельно проверены поздние hooks/retries, busy без перезаписи результата,
прерывание копирования recovery, rollback units, отказ stamp cleanup и прерывание
между rename STATE и удалением config. Исправлен перенос box-drawing divider,
который ошибочно резервировал вторую клетку как эмодзи.

Пакет готовится локально; реальные Ubuntu 22.04/24.04/26.04, динамические bans,
новое SSH-подключение, серверные SIGKILL/reboot и ACME требуют отдельной приёмки.
Эти локальные тесты не подтверждают работоспособность всех сетевых конфигураций.
ТЗ и AGENTS.md исключены из Git и экспорта; прежняя Git-история не переписывается.

## Ширина значков и повторная установка 1.4.4, 11.10.2026

Приёмка фиксирует две модели SSH-терминала: нарисованный эмодзи занимает две
клетки, а курсор после него продвигается на одну или две. В обоих случаях
между значком и текстом должна остаться ровно одна пустая клетка, при одном
ASCII-пробеле в данных. Предыдущие тесты проверяли пробел, но использовали
только модель курсора шириной две клетки и не воспроизводили наложение значка.
На TTY CellStream отслеживает колонки и явно ставит курсор перед пробелом
после эмодзи (CHA); учитываются SGR, grapheme/VS16/ZWJ/flags, частичные записи,
общий stdout/stderr, ввод, CR/LF, tab и перенос строки. NO_COLOR сохраняет
позиционирование; dumb/redirect не получают ANSI.

Режим установки выводится вертикально: 1 Caddy, 2 свой веб-сервер, 0 выход;
заголовок и номера выделены как в главном меню. Первая диагностика теперь
получает сохранённую проверенную конфигурацию: прежние нестандартные порты
и install_id распознают собственный Caddy. Чужой слушатель по-прежнему
блокирует установку до изменений. HTTPS Caddy слушает постоянно; HTTP-01
включается временно при реальном выпуске/продлении. Повторная установка
сохраняет прежний ACME account и сертификат, не использует принудительный выпуск.

Локально: **440 passed, 7 skipped** на Windows (symlink/POSIX permissions),
Ruff и синтаксис Bash прошли. Все 14 групп controlling PTY в WSL Ubuntu
успешны: обе модели курсора, no-color/NO_COLOR, dumb/redirect, край строки,
частичные VS16/SGR/CSI, общий stdout/stderr с обычной буферизацией,
настоящий ввод, Ctrl+C/EOF и вертикальный выбор режима. Просмотрены кадры
80×40 и 48×20; длинный отчёт сохраняет сводку, EOF восстанавливает прокрутку.
Реальная установка, ACME, firewall и изменения серверов не выполнялись.

## Повторная установка и подтверждения, 11.10.2026

В 1.4.1 повторная установка после `uninstall` использует входящий проверенный
пакет. Прежний runtime в `/opt/tenant-selfsteal` не подменяет его версию.
Данные прежней установки остаются в отдельном root-only backup с датой и временем.
При существующей конфигурации переход на другую версию требует `update`.
Все подтверждения используют `[y/N]`; только `y`/`Y` разрешают действие,
пустой ответ, `no`/`n` и прежнее русское `да` его отменяют.

Условия приёмки фиксируются до реализации:

- После удаления 1.3.3 установка входящего пакета 1.4.1 сохраняет в `/opt`
  именно 1.4.1; глобальный launcher обращается к этому пакету.
- Отмена плана и выбор инструкции не заменяют сохранённый runtime.
- Чужие каталоги и символические ссылки не перезаписываются.
- Действующая установка другой версии возвращает `UPDATE_REQUIRED`.
- Сбой замены пакета оставляет прежний пакет восстановимым.
- Удаление сохраняет данные в отдельной папке и не перезаписывает прежние backup.
- ACME использует только собственное хранилище; сторонние аккаунты не импортируются.

Регрессионные проверки выполняются без реальных Docker/UFW/ACME операций.
Полный прогон: **314 passed, 7 skipped** на Windows (symlink/POSIX permissions).
Ruff и offline PTY-приёмка в WSL Ubuntu прошли. Реальная установка и выпуск
сертификата не выполнялись.

## Автономный публичный пакет

Исходники: [README](../README.md).
Исходный selfsteal 2.10.0 и соседний репозиторий не изменены.

CLI: install, configure (согласованный проверочный порт), status, diagnose,
renew, update, uninstall. Runtime Python stdlib, pinned acme.sh 3.1.6,
Caddy 2.11.4-alpine с OCI digest и Compose v5.6.0 с SHA256 для amd64/arm64.
Все лицензии поставляются; MIT адаптации не заменяет GPLv3 отдельного acme.sh.

ACME account/config сохраняются. HTTP-01 standalone временно открывает только
свой tagged UFW-rule; существующее разрешение не удаляется. Для другого
firewall требуется явный manual mode и инструкция. Caddy читает рабочие cert/
key через каталог поколений, публичного backend HTTP 80 нет, HTTPS доступен
только на loopback. Проверяются SAN/срок/цепочка/key и фактически выдаваемый
сертификат с SNI/h2; ошибка откатывает поколение. Self-signed fallback отсутствует.

В 1.3.0 мастер сокращён до домена и трёх портов; подробности — в diagnose.
firewall_setup.py строит read-only план включения UFW, сохраняет SSH и
обнаруженные службы, резервирует конфигурацию и готовит независимый watchdog.
Включение разрешено только после подтверждения плана и повторных проверок.
Для неизученных firewall/Docker-схем автоматическая активация запрещена.

Systemd timer проверяет необходимость каждые 6 часов с RandomizedDelay 45 минут;
due/ARI определяет acme.sh, нет force issuance или независимого cron. Общий
flock, transient ACME cgroup, ограниченный срок, tagged marker, watchdog и
boot recovery покрывают очистку и восстановление. Update принимает только
явный URL/версию/SHA256, проверяет архив, сохраняет предыдущий пакет и имеет
устойчивый журнал переименований. build_release.py создаёт исходный архив
с файлами в корне и checksum; никаких публикаций не выполняет.
