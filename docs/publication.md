# Подготовка публичного репозитория

Исходники клиентского пакета публикуются отдельно от приватного «Транзита»:
https://github.com/donkyboss1/transitclient, ветка `main`.

Единственный исходный проект находится в `H:\Dev\transitclient`.
Сборка выполняется локально из его каталога:

```bash
python3 build_publication.py
```

Команда собирает только файлы клиентского пакета и создаёт в этом проекте:

- `dist/transitclient-<VERSION>.tar.gz` и файл SHA256;
- `install.sh` с URL этого архива, точной версией и SHA256;
- `.gitignore` и `.gitattributes` для публичного репозитория.

`AGENTS.md`, локальные ТЗ и требования не входят в Git и релизные архивы.
Публичная документация ограничена implementation/integration/operations/publication.
Изменение `.gitignore` не очищает прежнюю историю Git: ранее опубликованные
версии остаются в истории. Перезапись истории не выполняется этой командой.

`install.sh` находится вне архива, поэтому хеш не зависит от самого себя.
Клиент скачивает один Bash-скрипт; остальные файлы он загружает и проверяет сам.
Токены GitHub, API «Транзита» и доступ к приватному репозиторию не нужны.

Перед публикацией проверьте diff и список файлов, затем отправьте исходники,
`install.sh` и `dist` одним коммитом. Команда из README заработает только после
push. Не переносите `.env`, настройки приватного проекта или весь его каталог.

Для следующего релиза измените `VERSION` и пересоберите публикацию. Не заменяйте
архив уже опубликованной версии. Сборщик разрешает повторную сборку с тем же
содержимым; при другом SHA256 останавливается до замены архива, его checksum
и bootstrap. Сначала увеличьте VERSION.

Для обновления существующей установки пока нужна явная команда с URL нового
архива, его версией и SHA256:

```bash
sudo transitclient update --package-url HTTPS_URL --version VERSION --sha256 SHA256
```

Публичная публикация не подтверждает серверную приёмку Ubuntu или успешность
выпуска сертификата. Эти проверки выполняются отдельно.
