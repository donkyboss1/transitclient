# Transit Client — правила работы

## Отдельный проект

- Рабочая папка: `H:\Dev\transitclient`.
- Публичный репозиторий: `https://github.com/donkyboss1/transitclient`, ветка `main`.
- Всё, что относится к клиентскому установщику, его сайтам, тестам, документации
  и релизам, изменять и публиковать только здесь. В `H:\Dev\TRANSIT` копий нет.
- Основной «Транзит» отвечает за бот, API и HTTP-маршрут релея. Не переносить его
  код, реквизиты или инструкции доступа в этот публичный репозиторий.
- Сохранять пользовательские изменения и авторские уведомления лицензий.

## Установщик

- Caddy всегда работает через собственный Docker Compose.
- Не менять чужие службы, конфигурации, контейнеры или сетевые правила молча.
- Три порта различаются: VPN inbound 443, проверочный HTTP 8080,
  локальный HTTPS 9443. Команда управления — `transitclient`, `transit` не менять.
- Работа без API/токенов «Транзита». Сертификат и ключ остаются у клиента.
- Уточнение владельца 10.10.2026 для 1.3.0: мастер спрашивает только домен и
  три порта, автоматически определяет доступ ноды к Caddy. Технический отчёт —
  в diagnose. Слушатель на 443 не считать доказательством веб-сервера.
- UFW по умолчанию готовится автоматически: резервная копия, сохранение SSH
  и открытых TCP/UDP-служб, затем включение ранее выключенного UFW с watchdog.
  Не сбрасывать политики и чужие правила. Конфликты/неполная диагностика
  блокируют активацию; постоянные разрешения сохранения доступа не удалять
  при uninstall. HTTP-01 открывается временно, с очисткой только собственного UUID.
- С 1.3.1 обнаруженные iptables/ipset-правила Fail2Ban показывать как
  FIREWALL_FAIL2BAN_PRESENT; не обходить защиту автоматическим включением UFW.
  Интеграция Fail2Ban/UFW пока не реализована. manual сохраняет текущий firewall.
- README короткий и клиентский; технические инструкции — в `docs`.
- Сайты-заглушки скачивать только из закреплённого источника с проверкой хешей;
  смена сайта сохраняет прежний сайт и допускает откат.
- В 1.2.0 доступны 11 шаблонов, random/builtin/rollback и команда `template`.
  Каталог фиксируется в `templates.json`; файлы активного сайта — `site/current`.
- С 1.2.1 интерактивный bootstrap через pipe + sudo отклоняется до установки.
  Команда README скачивает скрипт во временный файл; от root запускает без sudo.
  Причина зависания конкретного sudo/SSH подтверждается отдельно, не по одному логу.
- Реальные установки, изменения серверов и выпуск сертификатов требуют отдельного
  разрешения владельца. Локальные проверки их не заменяют.
